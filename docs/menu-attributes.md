# 메뉴 속성 기준표 (v1, 2026-10-25)

메뉴 데이터 v2(S1, US-06)에 값을 넣을 때 이 표를 기준으로 합니다. 애매하면 "가장 흔하게 파는 형태"를 기준으로 정하고, 새로 정한 판단은 맨 아래 "판단 기록"에 한 줄 추가합니다.

공통 원칙

- 기준 형태: 서울의 평범한 식당에서 1인분으로 시킬 때 나오는 가장 흔한 형태. (예: "떡볶이"는 분식집 떡볶이, 국물떡볶이·로제떡볶이가 아님)
- 질문에 쓰이는 속성은 사용자가 "그렇다/아니다"를 바로 느낄 수 있는 쪽으로 정합니다. 요리 분류학보다 먹는 사람의 체감이 우선입니다.
- 기피 태그만 예외로 보수적으로 붙입니다. 조금이라도 들어가면 붙입니다 (알레르기·기피는 틀리면 안 되기 때문).

## 1. 나라별 `cuisine`

| 값 | 키 | 판단 기준 | 예 |
|---|---|---|---|
| 한식 | `korean` | 한국 가정식·백반·고깃집 메뉴 | 김치찌개, 삼겹살, 비빔밥 |
| 중식 | `chinese` | 한국식 중국집 + 마라 등 중국 요리 | 짜장면, 탕수육, 마라탕 |
| 일식 | `japanese` | 일본식 덮밥·면·튀김·회 | 돈까스, 라멘, 초밥 |
| 양식 | `western` | 유럽·미국·멕시코 요리 | 파스타, 피자, 햄버거, 타코 |
| 분식 | `bunsik` | 분식집에서 파는 메뉴. 나라보다 "분식집 메뉴인가"가 우선 | 떡볶이, 김밥, 라볶이, 순대 |
| 아시안 | `asian` | 동남아·인도 등 한중일 외 아시아 | 쌀국수, 팟타이, 똠양꿍, 나시고랭 |

- 한식과 분식이 겹치면 분식집에서 주로 사 먹으면 분식입니다 (떡볶이 → 분식, 칼국수 → 한식).
- 돈까스는 일식으로 둡니다 (경양식 돈까스도 "돈까스가 당기세요?"에서 같은 답이 나오므로).

## 2. 주재료 `base`

먹고 나서 "무엇으로 배를 채웠나"를 기준으로 하나만 고릅니다.

| 값 | 키 | 판단 기준 | 예 |
|---|---|---|---|
| 밥 | `rice` | 밥이 같이 나오거나 밥이 요리의 중심 | 김치찌개, 비빔밥, 덮밥, 국밥, 볶음밥 |
| 면 | `noodle` | 면이 중심 | 짜장면, 라멘, 쌀국수, 파스타 |
| 빵·밀가루 반죽 | `bread` | 빵, 또띠아, 피자 도우, 반죽 튀김 | 피자, 햄버거, 샌드위치, 타코야끼 |
| 고기 | `meat` | 고기 자체가 메인이고 밥은 곁들임 | 삼겹살, 족발, 탕수육, 스테이크 |
| 기타 | `etc` | 위 넷에 안 맞음 (떡, 채소, 회 등) | 떡볶이, 연어 샐러드, 사시미 |

- 찌개·탕에 공깃밥이 기본으로 나오면 `rice` 입니다. 고기 국물이어도 갈비탕·삼계탕처럼 "고기를 뜯는" 게 중심이면 `meat`.
- `기타`는 기획서의 4가지에 이 표에서 새로 더한 값입니다. 떡볶이·샐러드를 억지로 면·빵에 넣으면 "면 요리 어때요?"에 떡볶이가 올라오는 문제가 생기기 때문입니다.

## 3. 국물 `soup`

| 값 | 판단 기준 |
|---|---|
| 있음 `true` | 숟가락으로 떠먹는 국물이 요리의 중심 (찌개, 탕, 국밥, 국물 면) |
| 없음 `false` | 국물이 없거나, 소스·양념 수준 (볶음, 구이, 비빔, 소스 면) |

- 경계 예: 물냉면 있음, 비빔냉면 없음, 짬뽕 있음, 마라샹궈 없음, 떡볶이 없음, 카레 없음 (소스로 봄).

## 4. 맵기 `spicy` (0~3)

| 값 | 기준 | 예 |
|---|---|---|
| 0 | 전혀 안 매움. 아이도 먹음 | 짜장면, 된장찌개, 돈까스, 초밥 |
| 1 | 살짝 칼칼함. 매운 걸 못 먹는 사람도 먹을 만함 | 제육볶음(순한 집), 깐풍기, 마라탕 1단계 |
| 2 | 신라면 정도. 매운 걸 못 먹는 사람은 힘듦 | 김치찌개, 짬뽕, 닭갈비, 떡볶이 |
| 3 | 신라면보다 확실히 매움. "매운 음식"으로 골라 먹는 수준 | 불닭류, 엽떡 오리지널, 마라탕 3단계 이상 |

- 단계를 고를 수 있는 메뉴(마라탕 등)는 가게 기본값으로 정합니다.
- 질문 "매운 게 당기세요?"의 예는 맵기 2 이상을 매운 메뉴로 봅니다.

## 5. 온도 `temperature`

| 값 | 키 | 판단 기준 |
|---|---|---|
| 뜨거움 | `hot` | 데워서 따뜻하게 나옴 |
| 차가움 | `cold` | 차갑게 또는 상온으로 나옴 |

- 경계 예: 비빔밥 뜨거움 (밥이 따뜻함, 현재 데이터는 `cold`라 S1에서 수정), 족발 차가움, 초밥·샌드위치 차가움, 메밀소바 차가움.

## 6. 무게감 `weight`

먹고 난 뒤 포만감과 기름진 정도를 합쳐서 봅니다.

| 값 | 키 | 기준 | 예 |
|---|---|---|---|
| 가벼움 | `light` | 먹고 나서 더부룩하지 않음. 기름기 적음 | 샐러드, 메밀소바, 샌드위치, 쌀국수 |
| 보통 | `normal` | 평범한 한 끼 | 김치찌개, 비빔밥, 초밥, 짜장면 |
| 든든 | `heavy` | 배부르고 기름짐. 먹고 나면 졸림 | 돈까스, 삼겹살, 피자, 순대국밥, 마라샹궈 |

## 7. 가격대 `price` (1인 기준, 서울 평균 매장가)

| 값 | 키 | 기준 |
|---|---|---|
| 1만원 이하 | `low` | 10,000원 이하 |
| 1~2만원 | `mid` | 10,001 ~ 20,000원 |
| 2만원 이상 | `high` | 20,000원 초과 |

- 여럿이 나눠 먹는 메뉴(삼겹살, 족발)는 1인분 + 밥·음료 정도의 1인 몫으로 봅니다.
- 물가가 바뀌면 이 표의 기준 금액을 바꾸고, 메뉴 값은 다시 검사합니다 (`npm run check:menu`, S4).

## 8. 먹는 방식 `serving`

| 값 | 키 | 판단 기준 |
|---|---|---|
| 매장 | `dine_in` | 배달하면 맛이 크게 떨어지거나 매장에서 직접 구워야 함 |
| 배달 | `delivery` | 주로 배달로 먹음 (매장 취식이 드묾) |
| 둘 다 | `both` | 어느 쪽도 흔함 |

- 경계 예: 삼겹살 매장 (구이), 라멘 매장 (면이 불음), 족발·보쌈 둘 다, 피자 둘 다, 짜장면 둘 다.
- 상황 질문 "나가서 드실 건가요?"에 "아니오"(배달)면 `dine_in`만 빠집니다.

## 9. 인원 `party`

| 값 | 키 | 판단 기준 |
|---|---|---|
| 혼자 가능 | `solo` | 1인분 주문이 흔함 |
| 2인 이상 | `group` | 보통 2인분부터 팔거나 나눠 먹는 요리 |

- 경계 예: 삼겹살 2인 이상 (대부분 2인분부터), 족발·보쌈 2인 이상, 양장피·동파육 2인 이상, 닭갈비 2인 이상, 마라샹궈 혼자 가능 (무게로 담음).
- 상황 질문 "혼자 드시나요?"에 "예"면 `group`만 빠집니다.

## 10. 기피 태그 `avoidTags`

알레르기·취향 설정(로그인 직후 시트, 마이페이지)에서 고른 태그가 하나라도 붙은 메뉴는 질문 없이 시작 전에 뺍니다. 화면에서는 "알레르기"와 "안 먹어요" 두 묶음으로 보여 주지만 저장과 동작은 같습니다.

**알레르기 묶음**

| 태그 | 붙이는 기준 |
|---|---|
| 밀가루 | 면·빵·튀김옷·만두피 등 밀가루가 주재료로 들어감. 쌀국수·메밀소바(순메밀 기준)는 안 붙임 |
| 메밀 | 메밀면이 들어감 (메밀소바, 냉면) |
| 유제품 | 우유·치즈·크림·버터·요거트가 기본 레시피에 들어가면 양과 관계없이 붙임 (피자, 파스타, 리조또, 라자냐, 로제떡볶이, 햄버거·타코·부리또의 치즈, 부대찌개의 치즈, 일식 카레 루, 커리와 난, 탄두리 치킨) |
| 달걀 | 달걀이 기본 레시피에 들어가면 양과 관계없이 붙임 (덮밥의 계란, 지단, 계란 프라이, 삶은 달걀, 계란 튀김옷, 마요네즈, 빵 반죽) |
| 갑각류 | 새우·게가 기본으로 들어감. 갑각류면 `해산물`도 함께 붙임 (검사 스크립트가 확인) |
| 해산물 | 생선·조개·새우·오징어 등이 재료로 들어감. 멸치 육수만 쓰는 경우는 안 붙임 |
| 견과류 | 땅콩·견과류가 기본으로 올라감 (팟타이) |

**안 먹어요 묶음**

| 태그 | 붙이는 기준 |
|---|---|
| 매운맛 | 맵기 2 이상이면 자동으로 붙임 (직접 입력하지 않음) |
| 날것 | 익히지 않은 생선·고기 (회, 초밥, 육회, 회덮밥) |
| 돼지고기 / 소고기 / 닭고기 | 그 고기가 주재료이거나 기본으로 들어감 (햄·소시지는 돼지고기). 육수에만 쓰는 경우는 안 붙임 |
| 오이 | 오이가 기본으로 들어감 (냉면, 비빔밥 일부, 김밥) |
| 가지 | 가지가 들어감 |
| 고수 | 고수가 기본으로 올라감 (쌀국수, 분짜, 반미, 똠양꿍, 타코, 부리또) |

- 알레르기 묶음은 비중이 아니라 포함 여부로 붙입니다. 조금이라도 기본으로 들어가면 붙이고, 애매하면 붙이는 쪽을 고릅니다. 안 먹어요 묶음(고기·채소)은 주재료이거나 기본으로 들어갈 때만 붙입니다.
- 그래도 가게마다 재료가 달라서 태그는 "보통 이렇게 나온다" 기준입니다. 설정 화면에도 알레르기는 주문할 때 다시 확인하라고 안내합니다.
- 대두(간장·된장)는 거의 모든 한식에 들어가 태그로 빼면 추천할 메뉴가 남지 않아 넣지 않았습니다.
- 새 태그를 더하면 `menuData.ts`의 `ALLERGY_TAG_OPTIONS` 또는 `DISLIKE_TAG_OPTIONS`와 이 표를 같이 고칩니다. 검사 스크립트는 이 목록을 그대로 씁니다.

## 판단 기록

새로 애매한 메뉴를 만나 기준을 정하면 여기에 한 줄씩 남깁니다.

- 2026-10-25 · 주재료에 `기타` 추가 (떡, 샐러드, 회)
- 2026-10-25 · 분식은 나라보다 "분식집 메뉴인가"를 우선
- 2026-10-25 · 매운맛 태그는 맵기 2 이상에서 자동 계산
- 2026-10-25 · 메뉴 100개로 확장 (US-08, US-09). 아래는 이번에 정한 경계 사례
  - 냉면(물·비빔): 메밀에 밀가루·전분을 섞는 게 흔해서 `밀가루`. 메밀소바는 기존대로 순메밀 기준으로 둠

## v2 타입 (S1에서 확정)

실제 타입과 데이터는 `frontend/src/constants/menuData.ts`에 있습니다. 초안과 달라진 점:

- 나라별은 `cuisine` 키 대신 `category`에 한국어 라벨(`'한식'`, `'분식'` 등)을 그대로 씁니다. 화면 표시와 서버 기록(`category`)에 이미 쓰던 값이라 바꾸지 않았습니다.
- `avoidTags`에는 매운맛을 넣지 않습니다. `getAvoidTags(item)`이 맵기 2 이상이면 매운맛을 붙여 줍니다.
- 값 검사는 `frontend`에서 `npm run check:menu`로 합니다 (`frontend/scripts/checkMenu.ts`). `npm test`도 같은 검사를 돌립니다.

## 데이터 검사 `npm run check:menu`

메뉴를 추가하거나 고친 뒤 `frontend` 폴더에서 실행합니다. 오류가 하나라도 있으면 실패(exit 1)합니다.

- 오류 (✗): 이름·이모지·설명 누락, 허용값이 아닌 속성, 기준표에 없는 기피 태그, `avoidTags`에 직접 넣은 `매운맛`, 같은 태그 중복, 메뉴 이름 중복, 메뉴 100개 미만, 나라별 분류 하나라도 8개 미만
- 확인 필요 (!): 실패는 아니지만 기준표상 어색한 조합. `날것`인데 뜨거움, 면·반죽 요리인데 `밀가루` 없음. 밀가루가 정말 없는 메뉴면 스크립트의 `WHEAT_FREE` 목록에 이름을 추가합니다.
